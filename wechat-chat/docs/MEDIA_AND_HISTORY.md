# メディア受信と過去履歴

2026-11-10更新。Weixin 4.1.8.107（中国語UI）と正規認証済みwxautox4 41.2.3で検証しました。

## 操作と対応範囲

会話内の画像・ファイルは「読み込む」、ボイスは「文字起こしを読み込む」を押します。監視対象の会話で、元のメッセージを現在のWeChat UIから再確認できる場合だけ取得します。保存後はWindowsがオンラインなら、認証済みの携帯ブラウザから閲覧・ダウンロードできます。

| 種類 | 実装・検証 |
|---|---|
| 画像 | SDKのdownloadで保存・表示。SDK単体、常駐API、Chrome 390px/320pxで実機検証成功 |
| ファイル | SDKのdownloadで保存・認証付きダウンロード。実機で取得し、Chromeから本体のバイト数まで確認 |
| ボイス | SDKのto_textによるWeChat文字起こしを保存・表示・検索。44文字の実結果で検証成功 |
| ボイス原音 | 取得・再生は未対応。プレーヤーを表示しない |
| 動画 | 種別の識別とdownload呼出し、保存後のファイルダウンロードを実装。本体の実取得は未検証 |
| メディア送信 | 未対応 |

添付の種別ラベルと本文を区別します。ボイスは「WeChatの文字起こし」と表示し、OpenAIには送りません。SDKが原本を返したか判別する情報はなく、画質・原本一致は保証しません。WeChat内で取得不能・期限切れの添付を復元したとは表示しません。

## 保存と取得

- migration 007のattachmentsテーブルに、メッセージとの対応・取得状態・ファイル名・サイズ・文字起こしを保存。
- 本体はDBと同じ親ディレクトリの「DB名-attachments」フォルダ。SDKの保存先を専用一時フォルダに限定し、領域外のパスを拒否。完全な書き込み後にSHA-256の名前で保存します。
- 1ファイル100 MBまで。本人の操作で取得キューへ登録し、UI操作は送信・同期と直列化。失敗・中断後は自動再試行しません。
- 取得後は同じメッセージを更新し、ID・取得時刻・未読数を増やしません。workerの受信ACKで更新を消さないよう、新しい連番を付けます。
- インライン画像は実バイトで判定したPNG/JPEG/GIF/WebPのみ。HTML/SVG等を実行可能なページとして配信しません。添付はnosniff・sandbox・no-storeで配信します。
- 情報・取得指示・本体はすべて認証必須。保存キー・ファイルパスはブラウザに返さず、Service WorkerもAPI・添付をキャッシュしません。
- ファイル名と文字起こしも検索対象。ファイル本文解析・AIへの自動アップロードはありません。

APIはGET /api/attachments/{id}、POST /api/attachments/{id}/fetch、GET /api/attachments/{id}/contentです。POSTは受付後すぐ202を返し、進捗はWebSocketとGETで確認します。本体はHTTP Rangeにも対応します。

バックアップはアプリ停止後、アプリDB・worker DB・添付フォルダを一組として保存してください。DBだけでは添付本体は戻りません。保存は平文で、本人専用のOS権限とディスク暗号化が前提です。

## 過去の会話

最新: 全履歴の取得依頼に基づき、指定バックアップの実検査とPCの会話・履歴の巡回キューを追加しました。[現在の方法・制限](HISTORY_SYNC.md)を参照。以下の「後で提供」は以前の方針です。

本人の最新指示により、一括取り込みは後で提供されるバックアップを使います。大量の画面巡回による初回インポートは行わず、現在の監視窓から取得できた範囲を部分履歴として保存します。

バックアップの場所・形式・対象アカウントは未確認です。WeChat公式バックアップを汎用SQLite/JSONとして読めるとは仮定しません。公式バックアップの直接インポーターは未実装です。

受領後は原本を保持し、形式、添付との対応、アカウント・会話・メッセージ識別情報を確認してインポーターと重複照合を実装します。既存の画面由来の会話と名前だけで自動統合しません。正規復元が必要なら、本人の認証操作を含む手順を分けます。侵襲的な鍵抽出・プロセス注入等は採用しません。
