# AIアシストと会話整理

更新: 2026-11-09。OpenAI Responses APIへ接続する実装を追加しました。**稼働環境では外部AIは無効です。実モデルの疎通・翻訳品質は未検証**で、合成ProviderとHTTPモックで処理を検証しています。

## 使える操作

会話のヘッダーにある「AI」から開きます。

1. 翻訳・返信案・要約／決定事項・タスク候補を選ぶ。
2. 参照する受信／送信メッセージを選ぶ。翻訳は本文1件または入力中の下書き、それ以外は最大10件。
3. 「送る内容を確認」で、送信対象の本文と補足を確認する。この段階では外部通信しない。
4. 確認チェックを付けてAIを実行する。設定済みのOpenAIに、確認画面の内容と固定の処理指示だけを送る。
5. 訳文と原文を切り替える。返信案・訳文は明示操作で既存下書きの末尾へ追加し、4,000文字を超える場合は拒否する。送信は会話の送信ボタンで別途行う。
6. タスク候補は元発言・タイトル・期限候補を確認し、既存のタスク編集フォームで確定する。抽出だけで登録しない。

中国語→日本語、日本語下書き→中国語の両方を選べます。返信案の初期言語は中国語、要約・決定事項・タスク候補は日本語です。原文・生成結果・モデル・参照IDはローカルで確認できます。原文メッセージが表示範囲外の場合は、読み込んでから切替・タスク追加を行います。

## 設定と停止

Windows側の `.env` に次を設定し、アプリを再起動します。APIキーをブラウザやGitへ記載しません。

```dotenv
WECHAT_AI_ENABLED=false
OPENAI_API_KEY=
OPENAI_MODEL=
```

利用する場合だけ、本人がキーと利用可能なモデルを指定し、`WECHAT_AI_ENABLED=true` に変更します。モデルにはResponses APIとStructured Outputs対応が必要です。特定モデルを自動選択しません。API利用料金は別途かかります。設定値がそろっても、実際の疎通・品質を検証済みとは表示しません。

停止は `WECHAT_AI_ENABLED=false` へ戻して再起動します。実行中の処理は結果不明として扱い、自動再実行しません。設定を変更しなくても、確認チェックと実行操作なしで本文を外部へ送る処理はありません。

## データと同意

- 会話名・送信者名・アカウントID・外部メッセージID・他の会話は項目として送りません。本文中の名前などは自動匿名化しないため、確認画面で対象を選び直してください。
- 最大10件、送信データJSON合計12,000文字。自動で履歴を追加せず、全文同期済みと仮定しません。OCRの発言は誤認識を確認してから選びます。
- 確認内容は5分間有効。操作を変更した場合は再確認が必要です。サーバーは確認時のスナップショットを使用します。
- 外部呼出しは固定の `https://api.openai.com/v1/responses`。`store:false` を指定し、tools・会話連結・SDK自動再試行を使用しません。環境プロキシ・リダイレクトも使用しません。
- `store:false` はOpenAI側の一切の保持がゼロという意味ではありません。保持条件は本人の契約・データ設定に従います。
- 本文やAPIキーを操作ログへ出しません。プロバイダーのエラー本文も画面やログへ転記しません。
- 生成結果と確認後に送った翻訳用下書き原文をSQLiteに保存します。参照メッセージID・内容のハッシュ・Provider・モデル・日時・状態も保存します。SQLiteは平文で、OSディスク暗号化を前提にします。
- ブラウザのキャッシュ・localStorageに会話や生成結果を保存しません。アプリ認証後のAPIで取得します。

## 実装の境界

`ai_provider.py` がResponses APIへの通信と構造化出力を担当し、`ai_service.py` が確認内容・非同期ジョブ・結果検証・永続化を担当します。AIから送信Adapterやタスク登録を直接呼ぶ経路はありません。モデルが返したタスクの参照番号は、選んだ受信メッセージと一致検証して内部IDに変換します。

- `GET /api/ai/status`: 設定状態。キーは返さない。
- `POST /api/ai/preview`: `{chat_id, operation, message_ids, draft, target_language, instruction}`。確認用ID・送信予定本文を返す。外部通信なし。
- `POST /api/ai/translate`, `/reply`, `/summarize`, `/tasks`: `{preview_id, approved:true}`。202とジョブを返す。
- `GET /api/ai/jobs/{id}`: 同じジョブの結果確認。再生成しない。
- `GET /api/ai/chats/{id}/jobs`: 会話別の直近10件の生成履歴。

全APIに既存の認証を適用し、CookieによるPOSTにはOrigin照合も行います。実行は同時1件、受付頻度を制限します。確認IDが同じ再受付は既存ジョブを返します。処理中の再起動、通信タイムアウト、受付応答の欠落は、自動再試行せず結果照会を行います。

マイグレーションは `005_ai_jobs.sql`。画面は `ai-support.tsx`。APIキー不要のブラウザテストには、テストサーバーだけから注入する `SyntheticProvider` を使い、「テスト応答」と表示します。本番の環境変数で偽AIへ切り替える機能はありません。

## 優先度とタスク

「対応すること」とチャットの急ぎ順は、引き続き `LocalRulesProvider` の簡易判定です。期限らしい語句・質問・依頼・経過時間を使い、手動指定を優先します。この判定の `ai_connected=false` は外部生成APIの設定状態とは独立しています。画面にも簡易ルールと表示します。

未読・要返信・送信確認・タスク化・タスク完了を区別し、未確定の送信を再送しません。タスクは受信メッセージ1件につき1件です。複数発言から複数候補を抽出できますが、同じ発言への複数タスク保存は未対応です。相対的・不明な期限はAIに推測させず、本人が日付を指定します。

未実装: AIによる全会話の優先順位推論、日次まとめ、文体学習、登録済みタスクのタイトル／期限編集・削除、通知、外部カレンダー／タスクサービス連携。外部AIを未設定のままでも、チャット・ローカル検索・簡易優先度・手動タスクは利用できます。

## 実機検証

最初は本人が用意した架空の中国語・日本語で、翻訳の自然さ・数字・否定・敬語・固有名詞を確認してください。実会話を使う場合は、送る本文をその都度確認します。APIの利用可能モデル、料金、保持設定の確認も必要です。実WeChatの接続可否とは別の検証です。
