## 操作

設定 → **過去履歴の取り込み → PC内の会話・履歴を取り込む**。

1. 会話一覧を低頻度でスクロールし、観測できた名前・UI識別情報を収集します。同名で異なるUI識別情報が見つかる会話は除外します。
2. 発見した個人・グループを順番に読み取ります。常時監視の窓数上限とは独立した、読み取り専用のキューです。
3. SDK `GetHistoryMessage` の10秒単位のcallbackをページとして保存します。SDKがTimeoutErrorを返しても、宛先を読み取り後に再照合できたページは保持します。
4. 3ページ続けて追加がない会話は「取得範囲は一部」で巡回を終えます。これは最古の履歴へ到達した証明ではありません。

「一時停止」「続きから再開」を利用できます。PCのWeChatを操作するときは一時停止してください。アプリ再起動時も保存・チェックポイントを保持し、一時停止から再開します。WeChatのプロセスが変わった場合は「会話一覧から再確認」が必要で、古い会話と名前だけで統合しません。

一覧探索は前後の画面に同じ会話が残ることを確認して進めます。重なりを確認できない場合はスクロール量を戻し、それでも一致しなければ一時停止します。一覧探索中の再開は先頭から再確認しますが、保存済みメッセージと重複防止情報は保持します。

## 保存・安全性

- 履歴workerの `history_candidates`、`history_seen`、`history_job` で進捗を保持。同一ページの観測ID・受信箱・チェックポイントを一つのトランザクションで確定します。
- 受信箱の蓄積が400件を超えたら新しい読み取りを待機し、アプリDB保存後のACKを優先します。
- 履歴会話は `wxautox4:local:history:` で区別し、既存ライブ会話や送信先には自動結合しません。UIは「保存履歴」。その宛先へ送信できません。
- `historical=true` のメッセージで未読・通知を増やしません。SDKが返した日時は `sdk_display`、識別子は `sdk_observation`。どちらもWeChatの恒久ID・サーバーによる日時保証とは扱いません。
- SDKの観測IDが同じで内容が異なる場合は保存を中止。同一本文でもIDが違えば保持。SDKのID生成・UI再生成による重複や区別不能の限界は残ります。
- migration 009は本文を変更せず履歴フラグと時系列索引・バックアップ検査表を追加。古いメッセージを後から取得しても日時順で閲覧でき、検索/タスクから対象IDへ移動できます。
- 認証付きGET/POST `/api/history`。POSTはstart/pause/resumeだけで、任意のファイルパスや送信先・本文を受け取りません。外部AI・自動送信は追加していません。

## 取得できない範囲

折りたたみ・一覧外・削除済みの会話、同名・UI再生成で照合できない会話、PCへ移っていない期間、画面が公開しない種類は取得できません。一覧の静止やタイムアウトを「全履歴同期済み」とは表示しません。安全上の上限は一覧1,000ページ、1会話1,000ページです。

画像・動画・ファイル・ボイスは種別を保存しますが、巡回で本体や文字起こしを一括取得しません。ライブ監視にある添付の明示取得機能は維持しています。保存履歴とライブ会話の安全な統合・全会話への返信・全会話の常時監視は別途必要です。
