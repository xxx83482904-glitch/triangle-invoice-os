# 無料wxauto4で実際の会話を読む

2026-11-09。Windows 11 / Python 3.10.6 / Weixin 4.1.8.107（英語UI）/ wxauto4 41.1.7で検証しました。**個人の受信・自分の発言、グループの本文・送信者を取得し、SQLiteとブラウザへ反映できました。実送信は無効です。** OCRや有料Plusを使う方式ではありません。

## 起動

通常の `scripts/setup.ps1` が完了したアプリで実行します。

```powershell
.\scripts\setup-wxauto4.ps1
.\scripts\stop.ps1
```

`.env` の次の2項目を編集します。既存のキー、携帯設定、AI設定は維持してください。

```dotenv
WECHAT_ADAPTER=wxauto4
WECHAT_DB_PATH=data/wxauto4.sqlite3
```

```powershell
.\scripts\start.ps1 -NoBrowser
```

正規WeChatへのログインは本人が行います。PCで読みたい個人・グループ会話を開き、WeChatを前面に置きます。操作が3秒以上落ち着いてから、10秒以上の間隔で新しいテキストを最大1件ずつ解析します。件数が多いと取り込みに時間がかかります。表示済みの同じ部品は再解析しません。

アプリでは「無料wxauto4・読取」と表示されます。「チャット」に取り込めた会話が並びます。未選択の会話を携帯から開いても、PC側のWeChatは切り替えません。PCで別の会話を開くと、その会話の取得分が追加されます。

本人の許可で設定済みの携帯用HTTPS URL・アプリ接続キーはそのまま使えます。再起動後はアプリへの再ログインが必要です。実WeChatの送信ボタンは無効で、入力や返信案の作成だけでは送信されません。

## 取得範囲

| 情報 | 扱い |
|---|---|
| 現在の会話名・個人／グループ | `ChatInfo`、入力欄名、会話一覧内の一致数を照合 |
| 本文・受信／自分の発言 | 現在のメッセージ一覧のテキスト部品をwxauto4で解析 |
| 相手の表示名 | 取得できた表示名だけ保存。WeChatの恒久IDではない |
| 自分の表示名・アカウントID | 未取得。空値を保存し推測しない |
| 発言日時・WeChatメッセージID | NULL。取得日時は別の `observed_at` に保存 |
| 自分の過去の発言の配信状態 | `unknown`。「配信結果未取得」と表示。アプリの送信キューには入れない |
| 履歴 | 常に一部取得。表示外・未選択の会話・画像・音声・動画・ファイルは未取得 |
| 会話一覧 | 本文を取得した会話。`GetSession`で見える一覧が全友達・全グループとは限らない |

未読はこのアプリでの閲覧状態です。WeChatの未読と同じとは限りません。UI操作でWeChatの会話を開くと、WeChat側で既読になる可能性があります。

## 実装と副作用

`WindowsWxauto4Adapter` → 隔離Python worker → 無料wxauto4 → Windows UI Automation の構成です。workerは18秒上限、プロセス間mutexで同時実行を避けます。状態確認APIは画面操作を増やしません。

無料版の英語辞書の空欄と中国語固定セレクターを、このReaderプロセス内で実際の英語ラベルに合わせます。プロフィール取得で `ProfileWnd.topui` の例外が出るため、読み取り時はアカウント情報を未取得のまま扱います。WeChatの認証やライセンスを回避するものではありません。

wxauto4のメッセージ解析は、方向・送信者を調べるために対象の本文をフォーカスし、右クリックメニューを開閉します。**画面に一切触れないReaderではありません。** 前面の対象WeChatと会話名・部品ID・本文を照合し、最大2回のメニュー開閉だけ許可します。メニュー項目の選択、テキスト入力、会話切替、送信メソッドは拒否します。背景から前面を奪う処理も無効化しています。

ログイン画面、版違い、同名会話、会話切替との競合、解析エラーでは読み取りを停止します。通常のアプリ再起動は履歴・読み取り済み記録を保持します。

## 重複と再接続の限界

`source_key` はWeChatプロセスの起動時刻・ウィンドウ、会話名・種別、UI一時ID、本文から作った内部キーです。WeChatの正式な外部IDとして扱いません。SQLiteの `(chat_id, source_key)` を一意にし、同じキーで本文・方向・送信者が変わった場合はエラーにします。

今回、繰り返し取得、個人とグループの往復、バックエンド再起動で重複0件を確認しました。同じ本文を持つ別UI部品を2件保持する回帰テストもあります。ただし、UI部品の作り直し・ID再利用・改名・同名会話を完全には識別できません。異なる表示名の履歴を自動で結合しません。

WeChat自体の再起動・ログアウトを検出したら `scope_changed` 等で停止します。アカウントIDを取得できないため、同じアカウントと自動判定しません。**WeChat再起動後の再バインド画面と、旧履歴との安全な継続は未対応です。** `.runtime/wxauto4-reader.json` を安易に削除して同じDBに継続しないでください。現段階では開発者が本人のアカウント確認後に別DB・別読み取り記録として再設定する必要があります。

## 保存・通信

本文はDBと `.runtime/wxauto4-reader.json` に平文で保存されます。後者は再解析を抑える最大256件・2MBのローカル記録です。両方ともGit対象外で、OSのディスク暗号化と本人専用の権限を前提にします。標準出力の本文はバックエンドへの非公開パイプ専用で、診断ログには出しません。workerを端末で直接実行しないでください。

パッケージのログ・テレメトリーはimport前に無効化し、worker内のPython socket操作を拒否します。これはOS全体の通信遮断やバイナリの完全監査ではありません。外部AIは無効のままです。非公式UI操作の利用規約・アカウント制限リスクとライセンスの境界は [連携状況](../WECHAT_INTEGRATION_STATUS.md) に記録しています。

## 次の実機検証

1. PCで表示中の会話へ新しく届いたテキストの検出・WebSocket通知。今回は既存の実履歴の取り込みを検証し、新規着信を作為的に発生させていません。
2. 同名・改名、WeChat再起動、ログアウト・再ログイン、画面ロックからの安全な継続。
3. 送信先を恒久的に照合できる方法。本人が宛先と本文を指定して許可した後にだけ実送信試験。
4. 画像・ファイル、実AI翻訳、iPhone/Android実機。現在の成功として数えません。

自動テストは `pytest backend/tests -q` と `frontend` の `npm run test:e2e`。いずれも合成データを使い、WeChatへ送信しません。実測は [TEST_RESULTS.md](../TEST_RESULTS.md) を参照してください。
