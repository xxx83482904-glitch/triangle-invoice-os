# 無料版wxauto4の実機検証

2026-11-09。本人の「無料版でまず試す」という指定に基づく検証です。有料版の購入・認証・実メッセージ送信は行っていません。

## 今回の結果

| 対象 | 結果 | 観測 |
|---|---|---|
| wxauto4導入 | 成功 | 41.1.7、Python 3.10.6、隔離venv。常駐アプリの依存とは分離 |
| 正規WeChatの会話画面 | 成功 | 4.1.8.107、ログイン後のグループ会話を画面で確認 |
| 同梱UIAでの画面構造取得 | 失敗 | 1ウィンドウ、2ノード、対話部品0。本文・宛先の部品なし |
| `WeChat(resize=False, debug=False)` / 英語設定 | 失敗 | `main_window_not_found`、初期化完了前に停止 |
| 中国語設定 | 失敗 | 同じエラー。WeChat本体の表示言語は変更していない |
| `version='WeChat'` / 国際版指定 | 失敗 | 同じエラー。表示言語とクライアント種別を分けて確認 |
| `GetSession` / `GetAllMessage` の取得結果 | 未検証 | 初期化失敗のため呼び出しに到達せず。空リストを取得したという意味ではない |
| 個人・グループ送信、新着監視、添付ファイル | 未検証 | 呼び出していない |

無料版が要求するUIAクラスは `mmui::MainWindow`。実機では `Qt51514QWindowIcon` とコンテナーのみが公開されます。公称対応版でも、このPC・アカウントで利用可能とは限りません。内部原因は未特定で、有料版なら直るという証拠もありません。

## 再検証

アプリのセットアップ済みディレクトリで実行します。WeChatへのログインは本人が行い、会話画面を表示しておきます。

```powershell
.\scripts\setup-wxauto4.ps1
.\.venv\Scripts\python.exe -X utf8 .\scripts\check-wxauto4.py
```

初回セットアップはPyPIから `wxauto4==41.1.7` と依存を `.runtime/wxauto-venv` に導入します。実機で使用したPythonは3.10です。常駐アプリの `.venv`、`.env`、DB、WeChatの設定は変更しません。配布wheelはリポジトリに含めません。

ポリシーによりPowerShellスクリプトを実行できない場合は、アプリのPythonで次を実行できます。OSの実行ポリシーは変更不要です。

```powershell
.\.venv\Scripts\python.exe -m venv .runtime\wxauto-venv
.\.runtime\wxauto-venv\Scripts\python.exe -m pip install wxauto4==41.1.7
.\.runtime\wxauto-venv\Scripts\python.exe -X utf8 scripts\check-wxauto4.py --prepare
.\.venv\Scripts\python.exe -X utf8 scripts\check-wxauto4.py
```

セットアップは隔離環境の `param.py` にあるテレメトリー・ファイルログの既定値だけを、import前に無効化します。想定外の版・設定構造では停止します。認証・ライセンス・WeChatプロセスを変更しません。

試験は3設定を順に実行し、各プロセス15秒で打ち切ります。送信・会話切替・監視開始のメソッドは拒否します。取得できた場合も会話数・表示中のメッセージ数だけを残し、本文・名前・画像は保存しません。

終了コード0は「少なくとも1設定で表示中のメッセージ数が1以上」、2は「本文取得を確認できず」です。0でも全履歴同期・宛先ID照合・実送信成功を意味しません。今回の実測は2です。

結果は `.runtime/wxauto4-trial.json` に原子的に保存し、認証後の設定画面「無料版の検証記録」に表示します。保存日時のある過去の記録であり、現在の接続状態ではありません。設定画面を開き直すと最新の記録を読みます。検証記録からAdapter・DB・送信可否を自動変更しません。

## 通信とログ

Pythonのaudit hookでsocketの名前解決・接続・送信・bindを拒否します。実機ではUIA構造検査だけなら0件、WeChatクラス初期化では各設定3件の名前解決要求が拒否されました。呼び出し元は `get_wxauto_ads` でした。会話データは診断出力に含めません。

これはPythonで観測できる通信の抑止であり、OS全体の通信隔離やコンパイル済みライブラリの完全監査ではありません。検証用venv、wheel、私的な画面、JSON記録はGit対象外です。

## 次の実機試験の条件

通常の設定・起動条件でUIAに会話の部品が公開される環境を確認してから、次へ進みます。プロセス改変や暗号化DB復号で強制的に読み取りません。

1. 本人のテスト会話で、個人／グループそれぞれの本文・送信者・方向を画面と照合する。取得できない日時・IDはNULLまたは未取得として保存する。
2. 会話名の変更・同名会話・アカウント変更を試し、安全な宛先識別ができるまで送信を無効にする。
3. 対象会話の新着、既読・再表示、再起動、切断復帰を確認し、重複と取得漏れの範囲を記録する。監視対象外や表示外の履歴を完全取得と扱わない。
4. 宛先と本文を本人が指定して許可した後にのみ、個人・グループで1件ずつ送信する。結果不明は確認不能とし、自動再送しない。
5. 画像・ファイルは実際の無料版APIと取得範囲を別途検証する。AI送信は必要な本文を本人が確認し、接続設定を有効にした後に行う。

参考: [公式インストール・対応版](https://docs.wxauto.org/docs/install.html)、[WeChat API](https://docs.wxauto.org/docs/class/WeChat.html)、[Chat API](https://docs.wxauto.org/docs/class/Chat.html)。無料版とPlusの記述を混同せず、メソッドが存在するだけで動作確認済みとは扱いません。
