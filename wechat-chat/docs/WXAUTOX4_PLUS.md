# wxautox4 Plusへの切替

更新: 2026-11-10。本人の「Plusで進める」に従い、任意のPlus Adapterを追加しました。**コードと合成SDKテストまで。購入・認証・Plusでの実受信・実送信は未検証です。** 稼働中の無料Readerの実測と混同しません。

## このPCで次に行うこと

1. [公式サイト](https://wxauto.org/)で購入前に、Windows Weixin **4.1.8.107・英語UI** と wxautox4 **41.2.3** の対応を提供元に確認します。公式インストール資料はWeChat 4.1系を記載しますが、Siverの対応表は4.1.9以降です。現在の組み合わせの成功は保証できません。価格や返金条件は未確認です。
2. `wechat-chat` で `.\scripts\setup-wxautox4.ps1`。別venvへ固定版を導入します。認証やWeChat操作は行いません。
3. **購入・認証は本人がこのWindows PCで** `.\scripts\activate-wxautox4.ps1` を実行。コードは非表示入力し、アプリには保存しません。内部では公式の `wxautox4 auth activate` を呼びます。コードをチャットやGitへ貼らないでください。コマンド実行中はOSのプロセス情報に引数が現れるため、信頼できる本人用PCで行います。
4. 認証が終わったら、実機読み取りを開発者と確認します。切替は下記の設定を使い、実送信は無効のまま開始します。

```dotenv
WECHAT_ADAPTER=wxautox4
WECHAT_DB_PATH=data/wxautox4.sqlite3
WECHAT_PLUS_SEND_ENABLED=false
WECHAT_PLUS_MAX_LISTENERS=8
WECHAT_PLUS_LANGUAGE=en
```

`.env` を変更する前にアプリを停止・バックアップします。無料ReaderとPlusを同時に同じWeChatへ接続しません。`start.ps1 -NoBrowser` で既存のlocalhost/HTTPS配信を再開します。購入・認証だけで自動切替・送信有効化はしません。

## 実装した範囲

| 部分 | 動作 |
|---|---|
| `windows_plus.py` | 共通Adapter契約。非同期の隔離プロセス、40秒のRPC上限、障害時にプロセスを終了、5〜120秒の再試行間隔 |
| `plus_worker.py` | SDKを一つのプロセス内で保持。コマンドを直列化、標準入出力の私有パイプ、自由なメソッド呼出しを公開しない |
| `plus_sdk.py` | 41.2.3の `GetMyInfo / IsOnline / GetSession / AddListenChat / GetAllMessage / StartListening / StopListening / Chat.SendMsg` の薄いラッパー。認証API・Bot返信・一斉送信なし |
| `plus_core.py` | 同名除外・窓数上限・10秒に1窓の登録・60秒ごとの発見、アカウント照合、再接続、永続受信箱、送信済み受付の記録 |
| 共通キュー | 受付IDをworkerへ渡す。UI観測の `source_key` で自身の発言と送信結果を照合し、二重表示を防ぐ |
| UI | 監視中/発見/同名/登録失敗/上限/再接続を区別。現在の宛先だけ送信可。実送信は宛先・本文の確認画面を経由 |

GetSessionは**現在画面に公開される会話**です。友達帳全件や全グループではありません。Plusの監視は独立したチャット窓を必要とします。初期上限8窓（設定範囲1〜32）を超える会話・未発見の会話・履歴全件を取得済みと表示しません。UI非互換で窓の宛先照合に失敗した場合は、窓を繰り返し開かず停止します。

受信のcallbackは送信を呼びません。スレッド内でUI部品を最小限の値へ変換し、worker内のキューからSQLite受信箱に保存します。FastAPI側が保存後にACKした分だけ受信箱から除去します。worker再起動時も未ACK分を再取得し、アプリDBの一意制約で重複を防ぎます。上限超過時は停止と欠落可能性を明示します。

## 宛先・アカウント・送信結果

- `GetMyInfo()` の `wxid` を取得できなければ停止。初回のアカウントをハッシュで保存し、再接続時に別アカウントなら停止します。認証画面を自動操作しません。このSDKのフィールドと再取得の挙動は実機で照合が必要です。
- 個人・グループとも**公式の恒久チャットIDは未取得**。同一プロセスの独立窓、UI一時ID、入力欄の宛先名、SDKの名前・種別を照合した内部IDを使います。
- WeChat再起動・UI部品再生成後は同名だけで履歴を結合せず、新しい会話として保持します。以前の宛先への待機送信は中止します。恒久IDによる連続した履歴統合は未対応です。
- 実送信には環境設定での有効化に加え、現在の窓・アカウント・宛先の再検証と空の入力欄が必要です。既存のWeChat下書きを消しません。本文は4,000文字まで。
- SDKを呼ぶ**前**に受付IDと「確認不能」を永続化します。同じIDは再起動後も再送しません。SDK呼出しは独立Chatの `SendMsg` 一度だけで、メイン画面の名前検索・強制選択・リトライ付き送信は使いません。
- SDKの明示成功、送信前にはなかった自身の同文テキスト1件、送信後の宛先照合がすべて揃ったときだけ「送信確認済み」。それ以外は確認不能です。相手の受信・既読の保証ではありません。SDK内部の送信挙動も実機試験の対象です。
- SDKのUI由来のIDを正式なメッセージIDに見せません。発言日時未取得はNULL、取得日時と区別します。古い自分の発言は配信結果不明です。

## プライバシー・保存・ライセンス

任意venv `.runtime/wxautox4-venv` にインストールします。SDKの公開設定でファイルログをimport前に無効化し、標準出力・標準エラーはアプリのログに流しません。ライセンス処理の改変・回避は行いません。無料Readerと異なり、Plusの提供元による認証通信を一律遮断する設計ではありません。コンパイル済み配布物の通信全体を監査済みとは主張しません。

保存先はアプリDBに加え、同じフォルダの `wxautox4-worker.sqlite3`（DB名変更時は `<stem>-worker.sqlite3`）です。受信箱、ローカル会話情報、アカウントのハッシュ、送信受付・結果を保持します。**両方のDBを一組としてバックアップ**し、片方だけ過去へ戻さないでください。復元時は送信を無効にし、待機キューを確認します。ライセンスコードをこれらのDBに保存しません。

バックアップはアプリを `stop.ps1` で止めた状態で `data` フォルダ全体を本人専用の保存先へコピーします。稼働中のSQLite本体だけのコピーは避けます。OSディスク暗号化が前提です。すべてGit対象外です。

wheelの説明には古い4.0.5の記述やMITバッジもありますが、実際のLICENSEファイル同梱は確認できませんでした。商用ライセンス条件と認証が必要なPlusを、無条件にMITとして再配布しません。wheelや改変SDKはGitへ同梱しません。

## 認証後の実機検証手順（すべて未検証）

1. 正規WeChatでログイン。まず送信無効、1窓で接続し、版・UI言語・GetMyInfoのアカウントを本人のプロフィールと照合。名称だけをアカウントIDに代用しない。
2. 個人テスト会話の子窓・入力欄・本文・送信者・方向を照合。既存履歴の反復取得と、スマートフォンから新しく着信させた1件のWebSocket表示・重複0件を確認。
3. グループについて同様に確認。監視外の新着が取得済み扱いにならないこと、同名会話が除外されることを確認。
4. **本人が宛先と本文を指定して許可した後だけ**、隔離した試験環境で送信を有効にして1件送る。アプリ・WeChat双方を照合。SDK内部リトライ、入力欄のValuePattern、独立窓への正しい送信を確認。
5. 宛先窓を閉じる/切り替える、入力欄に下書きを残す、SDK応答を失う、APIを再送するケースで、誤送信・重複送信をしないことを確認。
6. WeChatの終了・再起動と本人のログイン後に監視が戻ることを確認。旧宛先への送信停止、履歴が別会話として残る表示、異なるアカウントでの停止、ロック・スリープ後の状態を確認。

問題があれば `WECHAT_ADAPTER=wxauto4` と元の `WECHAT_DB_PATH` に戻して無料Readerで保存済み履歴を閲覧できます。旧DBをPlusへ書き換えません。
