# WeChat連携状況

確認日: 2026-11-09。**Mockの双方向チャットは動作しています。個人用WeChatとの実送受信は未完成です。**

## 実装済み

| 機能 | Mock | Windows実機Adapter |
|---|---|---|
| `connect()` / `disconnect()` | 接続・切断を再現 | 読み取り専用診断の開始・停止。WeChat自体の認証・終了は操作しない |

## 実機で検証済み

- Windows 11、Node.js 24.18.1、Python 3.10.6。
- インストール済み `Weixin.exe` のファイルバージョン **4.1.15.56** を確認。
- UI Automationで実際のWeixinウィンドウを取得し、`login_layout_` と「Enter Weixin」のログイン待機を確認。
- 実装した `diagnose-wechat.py` でも `state=login_required`、`can_read=false`、`can_send=false`、同バージョンを確認。
- 診断が出力するのは状態・バージョン・ノード数等のみ。ユーザー名・本文・認証情報は出力しない。
- MockのUI・APIはこのWindowsでChromeを使い実行済み。実WeChatの送受信検証とは別扱い。

最終確認では「Scan to log in」のQRコード認証待機画面に変化しました。ユーザーの希望により、認証は後日行い、今回はMock版と接続診断までを成果物として受け渡します。実機の読み取り検証は本人の手動ログイン後に再開します。こちらでは認証・実アカウント送信を実行していません。

## リスク・制限事項

1. 個人WeChatの通常チャット用公式同期APIは利用していません。非公式UI自動操作にはTencentの利用規約への抵触・アカウント制限リスクがあります。[Tencent Weixin利用契約](https://oper.my-qcloud.com/cgi-bin/readtemplate?cc=CN&lang=en_US&s=default&t=weixin_agreement)
2. DLL注入・プロセス注入・認証回避・暗号化DB復号・通信プロトコル偽装は実装していません。プロセスの照会権限は `QUERY_LIMITED_INFORMATION` のみで、プロセスメモリを読みません。
3. UI公開情報が不十分なら読み取りも送信も停止します。ウィンドウ存在だけでログイン済み・ネット接続済みとは表示しません。
4. UI上の表示名は重複・改名し得ます。現状の実機では安全な宛先ID照合ができておらず、送信を実装していません。
5. 外部メッセージIDが得られない場合の指紋照合には取りこぼし・重複の可能性があります。DBの `identity_quality` / `timestamp_quality` に精度を記録する設計です。実機精度は未検証です。
6. 未取得の履歴は検索対象になりません。「送信確認済み」は相手の受信・既読保証ではありません。
7. ローカルSQLite自体は平文。OSディスク暗号化と本人専用権限が必要です。バックアップはアプリ停止後に行います。
8. 実機診断は別プロセス・8秒上限で実行し、UIAが応答しなくてもAPIを永久に停止させません。

## 次に必要な実機作業

運用構成はWindows常駐です。本人のスタートアップ登録、バックエンド障害からの復旧、SQLite履歴保持、携帯サイズからのMock送信を確認済みです。携帯版はPWAです。本人の外部公開許可を得てFunnelへ切り替え、携帯側のVPNは不要になりました。公開DNSの中継IP経由でHTTPS・認証・WebSocket・Mock送受信とChrome表示を検証済みです。携帯実機の操作・携帯回線は未検証です。Synologyにはデプロイしていません。AI連携は将来の別モジュールとして文書化しており、外部AIへの転送は無効です。

1. 本人が正規のWeixinクライアントでログイン完了し、読み取り検証可能なテスト会話を表示する。
2. 4.1.15.56のUIAでチャット識別、本文、送信者、方向、時刻、同一文面の複数発言を区別できるか確認する。本人の会話内容は診断ログへ保存しない。
3. 取得可能な項目だけを明示的な版別Readerへ実装し、過去履歴の範囲・欠落・重複精度を実機で確認する。
4. 安定した宛先IDが得られる場合に限ってSenderを実装する。まず本人が指定したテスト相手・本文について実送信の明示許可を得る。
5. 個人→グループの順で、宛先照合・送信前の画面切替・ネット断・確認不能・WeChat再起動を検証する。証拠が足りない送信結果は常に確認不能とする。

## 開発を引き継ぐ場合

Adapter契約は `backend/app/adapters/base.py`。UI固有処理は `windows_*` に限定し、Mockや共通キューへWeChatのセレクターを持ち込まないでください。現在の `WindowsUIAAdapter` は診断専用で、送受信処理の中身が完成しているように扱わないでください。実機検証なしに `can_send` / `can_read` をtrueへ変更しないでください。
