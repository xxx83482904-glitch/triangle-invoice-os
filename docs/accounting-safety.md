# 会計基盤の改善 (2026-10-08)

## 今回の範囲

登録権限、税額の端数計算、請求差額と未入金の集計を修正。既存データの一括変更と過去の請求書の再計算は行いません。本番反映は既存の GitHub Actions から Synology へデプロイする手順を使用します。

## 登録と承認

- `/register` は利用申請。権限選択を廃止し、サーバーが必ず `PENDING` を設定します。登録後の自動ログインはありません。
- 管理者のみ `/users` で申請を承認・却下できます。本人確認を行い、必要な担当権限を選んでから承認してください。
- 未承認・却下済み・削除済みの利用者は、ログインだけでなく既存のセッションからもアクセスできません。
- 承認処理は保存直前に管理者の現在の権限と申請の更新日時を再確認します。承認から管理者権限を付与することはできません。
- 登録・承認の操作履歴にはパスワードハッシュを返さず、通常の「元に戻す」の対象にもしていません。
- `accessStatus` がない既存利用者の権限は維持します。過去の公開登録で作成されたアカウントは自動で安全確認済みになるわけではないため、別途棚卸しが必要です。
- メール認証、招待メール、既存利用者の停止・権限編集、ログインの多要素認証は今回の対象外です。

## 税計算

- 数量×単価を円単位に丸めた明細金額を税率ごとに合計し、税額を税率ごとに1回だけ四捨五入します。
- 10%、8%、非課税、対象外を分けます。入力時の合計・新規保存・新規PDFの税率別内訳を共通計算にしました。
- 例: 15円×2行、10%の場合は税抜30円、税額3円、合計33円。
- 新規の明細入力による請求書・見積書には `taxRounding: "PER_RATE"` を記録します。見積書を編集保存したときも新計算になります。
- 古い書類は閲覧やPDF生成で金額を変更しません。計算方式未設定のPDFは以前の内訳を維持します。見積書から請求書への変換も、保存済みの金額と計算方式を引き継ぎます。
- 過去に発行済みの誤差は自動修正していません。取引先への再発行などの判断を伴うため、別途確認が必要です。

根拠: [国税庁 No.6371 端数計算](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shohi/6371.htm)

## 集計の定義

- 請求差額（税込）: 集計対象の発行請求書総額 - 受領請求書総額。入金時期では変動しません。内部の `grossProfit` フィールド名は互換性のため維持しています。
- 請求差額率: 請求差額 / 発行請求総額。発行額が0なら画面では `-`。
- 入出金差額: 記録済み入金 - 記録済み支払。請求差額とは別表示です。
- 未入金・未払い: 請求書単位で `max(請求額 - 対応する支払記録, 0)` を計算して合算します。ある請求書の過入金は別の請求書を相殺しません。
- 月別「発行分の未入金（現在）」: 発行月ごとに、現時点の記録から求めた請求書残高を合算。過去の月末残高ではありません。
- 月別「入金」「支払済み」: 入出金の記録日で集計。前月請求の当月入金は当月の入金額に入り、前月発行分の未入金を減らします。
- 日付のない請求書は「未設定」に残し、集計から消さないようにしました。
- 案件画面・ダッシュボード・レポート・案件CSVの名称を揃えました。案件CSVの末尾に「入出金差額」を追加しました。

これは請求ベースの業務集計です。収益認識時点、税抜売上・原価、仕訳・月次締めを備えた財務会計の粗利ではありません。正式な帳簿はマネーフォワード等と照合してください。

## 検証

```powershell
npm run test:accounting
npm run test:invoice-pdf
node --conditions=react-server --import tsx --test tests/documents.test.ts tests/estimates.test.ts tests/status-consistency.test.ts tests/document-editing.test.ts tests/banking.test.ts tests/moneyforward-client.test.ts tests/banking-sync.test.ts

```

追加テストは未承認ログイン、権限偽装、管理者以外の承認、古い申請の再送、税率混在、見積変換、過入金、月またぎ、削除済みデータを対象にしています。PDFは実際にレンダリングして確認しました。

`tests/prepare-accounting-preview.ts` は一時フォルダーに合成データを作ります。`tests/check-accounting-access.ts` はその検証サーバー専用で、実HTTP経由の申請・承認・ログイン・APIアクセス制限を検証します。本番では実行しないでください。
