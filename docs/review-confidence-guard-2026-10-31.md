# 推測分類の確認ガードと売上科目の提案（2026-10-31）

対象: 口座・カード明細（`/banking`）の分類と確認状態。

## 背景

- 明細の勘定科目には、ルール・確認済み履歴・摘要キーワード・AI候補のほかに、根拠の弱い「推測（GUESS）」候補がある。画面では赤い「推測・要確認」で表示される。
- これまで「選択を確認済みに」→保存で、推測のままの行もそのまま確認済み（分類確定）になり、推測だった事実は根拠文にしか残らなかった。
- 発行請求書と照合済みの入金が、科目未設定や売上系以外（雑収入など）のまま残っていても、画面は何も提案しなかった。

## 変更

### 推測のまま確認済みにするときの確認（P0-6）

- `saveBankEdits` は、未確認の行を確認済みにする編集で、その行の分類が推測（`isGuessClassification`）と判定される場合、`acknowledgeGuess: true` がなければ `GUESS_REVIEW_BLOCKER` のメッセージで拒否する。バッチ全体が保存されない（他の行も変更されない）。
- 推測の判定は保存後の状態で行う: 編集に `classificationConfidence: "GUESS"` が付いている、または科目・扱いを変えずに確認済みにしようとした行の保存済み確度が GUESS（確度未記録の旧データは表示ラベルの判定に従う）。
- 保留中・科目分割・振替/対象外の行は別のチェックが先に効くため、このガードの対象ではない。すでに確認済みの行のメモ編集、根拠なしに人が選び直した科目、キーワード推定（INFERRED）・過去実績（HISTORY）の行は対象外。
- 確認を伴って保存した行は `reviewed: true` のまま、確度 `GUESS` を保持し、根拠文の先頭に「推測候補を内容確認のうえ確定」を付ける。未確認に戻すと接頭辞は外れ、赤い推測表示に戻る。
- `saveBankEdits` の戻り値に `acknowledgedGuesses`（確認付きで確定した件数）を追加した。

画面（`banking-workspace.tsx`）:

- 「選択を確認済みに」「確認」を押したとき、選択中に推測のままの行があれば `BankGuessReviewDialog` を開く。対象行（日付・摘要・金額・科目・根拠、最大8件表示）を見せ、「内容を確認して確定」「推測の行を除いて確認済みに」「キャンセル」から選ぶ。
- 確定を選ぶと該当行の下書きに `acknowledgeGuess: true` が付き、保存確認ダイアログに「推測のままの分類を内容確認のうえ確定」と件数が表示される。未確認に戻すとフラグは消える。
- ダイアログも下書きも保存はしない。保存は従来どおり「確認済みを保存」などの明示操作。

### 照合済み入金への売上科目の提案

- `bank-sales-suggestion.ts` の `createBankSalesSuggester` は、発行請求書と有効な照合がある入金（INCOME・通常扱い・元明細あり・科目分割なし）について、現在の科目が売上系でなければ提案を返す。
- 売上系 = 収益グループの科目のうち名称に「売上」「売り上げ」「sales」「revenue」を含むもの。該当する名称がない場合は収益グループ全体を許容する。候補が1つならそれを、複数なら「売上高」を提案し、どちらでもなければ候補一覧のみ。
- 提案は `bankDisplayRows` が `salesSuggestion` として行に添える。データは変更しない。受領請求書との照合、出金、前受金・立替精算のような売上以外の入金を妨げない（提案であり、保存や確認のブロックではない）。
- 画面では分類ラベルの下に「請求書と照合済みの入金。売上系の科目「売上高」を提案」と「提案を採用」ボタンを表示する。採用すると手動選択（INFERRED・未確定）の下書きになり、根拠は「発行請求書と照合済みの入金（売上科目の提案を採用・未確定）」。保存と確認は従来の操作。

## 変更しないこと

- 既存データの一括書き換えは行わない。過去に推測のまま確認済みになった行は、確認済みのまま残る（確度ラベルは従来どおり「分類確定」）。見直すなら、確認済み→未確認→再確認で新しいガードが効く。
- AI候補・自動分類・同期の処理は変更していない。
