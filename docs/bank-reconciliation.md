# 銀行・請求書の照合

入口: `/banking/reconcile?company=JAPAN`。口座・カード明細、発行請求書、受領請求書、郵便物、入出金管理から移動できます。ADMIN / ACCOUNTING のみ参照・更新可能です。今回の実装はローカル検証用で、デプロイは別途明示的な依頼があったときに行います。

## データの扱い

- 銀行入金と発行請求書、銀行出金と受領請求書を照合します。郵便物は連携済みの受領請求書を参照し、二重集計しません。未連携の請求書・領収書の郵便物は件数を警告します。
- 「入金・支払い登録済み」と「銀行照合済み」は別です。従来の手入力や処理済み操作による支払いも、既存記録として銀行明細と紐づけられます。
- 候補は金額、摘要内の取引先名・請求書番号、期日・支払い記録日との近さから提示します。候補だけでは確定しません。同額の別請求書や名義の違いは利用者が原本で確認します。
- 一括振込は同じ銀行明細から複数請求書へ配分、分割払いは複数明細から同じ請求書へ配分できます。銀行未照合額、既存支払い未照合額、請求残高を超える登録は拒否します。
- 未登録分だけ支払いを新規作成します。全額に達した発行請求書は入金完了、受領請求書は支払済み、関連する郵便物は処理済みになります。一部入金・未払い残高は残します。
- 「状態を揃える」は有効な銀行照合がある書類だけで使えます。支払い金額を変えず、支払い合計に合わせて請求書・郵便物の状態を修復します。

## 安全性と制約

- Money Forward / 銀行への送金・仕訳書き込みはしません。原明細も変更しません。
- 同じ会社・同じ方向だけが対象です。カード利用、その他口座、振替、対象外、元明細消失、未来日付、無効金額は対象外です。カード引落しとカード利用を二重に照合しないでください。
- 取得明細に確実な通貨識別がないため、自動通貨換算は行いません。同じ通貨・同じ支払いであることを確定時に確認します。口座種別未設定は人による確認が必要です。
- 端数は小数2桁まで。手数料・為替差損益・値引きなどの差額を自動で消し込みません。差額は未照合額・未払い額として残ります。複数通貨の合計額は表示せず、一覧の金額は原明細の単位です。
- 下書き・取消・再発行済みの発行請求書、OCR待ち・保留・却下・アーカイブ済みの受領請求書、正の請求総額がない書類は照合できません。
- 照合後に銀行の金額・日付・摘要、請求書の金額・案件・取引先、支払い金額・日付が変更された場合は要再確認になります。過去の支払いは自動で改変しません。
- 解除では、元々あった支払い記録は残します。照合時に新規作成した未編集の支払いだけ取り消し、書類状態を再計算します。作成後に支払い記録が編集された場合や対象請求書が削除・別会社へ移動した場合は、既存記録保護のため解除を拒否します。対象記録を確認・復元してから解除してください。
- 全更新は既存のデータロック内で利用者の現行権限・会社・更新時刻を再検証します。監査ログと既存Undoに対応します。`bankReconciliations` は既存JSONストアの追加コレクションで、旧データは空配列として移行します。

## 検証

`npm run test:banking` に照合テストを含みます。権限・会社分離、二重登録、既存支払い再利用、分割・合算、差額、郵便連携、元データ訂正、解除・Undo、小数演算、1万件照合の集計を検証します。

`tests/check-bank-reconciliation.ts` は3018番の使い捨てプレビュー専用です。OS一時ディレクトリの `triangle-banking-preview-*`、架空ユーザー・口座を確認し、バックアップ後にサーバーアクション経由で保存・解除・Undo・権限制御を検証します。本番データには実行しないでください。

## 2026-10-10 操作と候補判定の改善

現行画面を合成データで確認したところ、銀行明細・AI欄・請求書候補が縦に続き、さらに確定ダイアログが必要でした。候補判定は金額の一致を重複加点し、取引先の口座名義や確定済みの照合履歴を利用していませんでした。

- PC・タブレットは銀行明細と請求書を横並び、スマホは明細一覧と詳細を切り替えます。明細選択はクライアント内で即時に切り替え、URLも同期します。
- 候補行を選ぶと、その場で照合額・銀行の残額・請求書の残額・確定ボタンを表示します。確定ダイアログと検索後のプルダウンを廃止し、AI確認は補助欄へ移動しました。
- 確定には同じ通貨・支払いであり二重計上しないことの確認が必要です。全額照合後は同じページの次の未照合明細、一部照合後は同じ明細を表示します。既存の解除・Undoも継続します。
- 全半角・ひらがな/カタカナ・法人略称、受領請求書の取引先の口座名義を比較します。漢字名の読みを推測して生成することはありません。
- 同一会社・口座・方向の確定済み照合から、同じ摘要と取引先の対応を再利用します。削除・証拠不整合・複数取引先に対応する摘要・短すぎる摘要は学習しません。推測候補だけでは学習しません。
- 金額だけ一致する候補は「要確認」。期日・記録日から90日超の同額候補は、名義などの別の根拠がなければ除外します。「すべて」と検索では引き続き選択可能です。
- 請求書番号が一致する候補を優先し、同条件が複数ある場合は要確認と表示します。金額の一致は一度だけ加点します。手数料差額は推定消込しません。
- 既存支払いの初期選択は金額一致、次に日付の近さを優先します。下書き・保留などの照合禁止条件や過払い防止は変更していません。
- 請求書起点の一覧は一致スコアの弱い銀行明細も除外せず、照合済みの記録と根拠の強い候補を先に表示します。
