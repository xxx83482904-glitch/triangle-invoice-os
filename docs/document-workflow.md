## 発行請求書の取込

- 案件を選び、PDF/JPEG/PNGをドロップまたはファイル選択。1回20件、各10MBまで。
- OCR対象は請求先・番号・発行日・期限・総額。請求先の登録先は選んだ案件のクライアント。OCR請求先は照合用に表示する。
- `DRAFT` と `needsReview: true` で取込。日付不明は空欄、金額不明は0、番号不明はOCR用仮番号。推測した税を加算しない。
- 原本ファイルを保持し、右側/スマホ下部でプレビュー・編集できる。複数の編集を保持して「すべて保存」。選択した発行請求書の状態をまとめて変更可能。
- 原本確認・番号・日付・正の金額が揃うまで発行済みにはできない。入金済みは入金記録から設定する。
- 同一会社内でファイルSHA-256または請求書番号が重複すると拒否。別名にした同じファイルも検出する。
- 保存時は担当案件と更新日時を検証し、競合時は変更を保持してエラーを表示する。
- 手入力で作る従来の請求書は残し、明細と金額の一致を維持する。OCR原本のPDF経路で空の請求書を再生成しない。

## 全書類

- `/documents?company=JAPAN` または `CHINA`。サイドバー・各書類画面から移動できる。
- 発行/受領請求書、郵便物、案件契約書、親書類が閲覧可能な添付書類を同じ一覧にする。
- 郵便物から受領請求書へ反映済みの書類は1行。月は受領請求書/郵便物のフォルダー月を優先する。旧契約書・追加添付は失わない。
- 月の折りたたみ、書類種別/分類/確認状態、検索、並べ替え、全選択、Shift範囲選択、CSV、原本プレビューを実装。
- 初期50行から追加表示。OCR本文は選択した書類だけ別APIで取得し、一番下に表示。
- スマホは縦型一覧、タブレット/PCは表形式。受領請求書の管理画面へ移る際は選んだ書類を開く。
- 郵便物担当は日本の郵便物と直接アップロードされた受領書類のみ。発行請求書・案件契約・金額集計は表示しない。
- プロジェクト担当は許可された種類かつ担当案件のみ。原本配信とOCR本文APIも同じ閲覧範囲を検査する。

## 共通修正

- インストール済み `pdf-parse` v2のAPIへ修正。従来のv1呼出しは本文解析に失敗していた。パーサーを必ずdestroyする。
- PDF解析・画像OCRをNext.jsサーバーの外部パッケージとして扱う。画像OCRキャッシュは `DATA_DIR/ocr-cache` に保存。
- `projectMoney`、ダッシュボード、集計、入金候補でOCR確認前/下書き/キャンセルの発行請求書を除外する。
- ローカルのread-modify-writeを単一プロセスの共通キューで直列化。同時OCR取込でも重複登録を防ぐ。
- public配下の従来ファイルURLもbeforeFiles rewriteで認証付き配信へ通す。
- 受領請求書の空フィルター時の無関係なプレビュー、書類切替時に前の書類のフォーム値が残る問題を修正。関連郵便物の原本情報も引き継ぐ。
- 郵便物の直接アップロード書類を無条件に処理済みにしていた表示を修正。
- 案件のダークモード集計欄を調整。スマホの集計欄を小さくし、担当者の受領請求書画面では合計を表示しない。

## 検証

- `npm run lint`、`npm run build`、`npm run test:documents`。単体/実PDFテスト11件。
- `tests/prepare-document-preview.ts` はOSの一時フォルダーに架空データ・PDF・PNGを生成する。本番データを読み書きしない。
- 生成先をDATA_DIR、配下uploadsをUPLOAD_DIRに指定し、DATABASE_URLと外部OCRのキーを未設定にしたローカルサーバーでテスト。
- `tests/check-document-api.ts` はローカル専用。権限、認証付き原本配信、担当外案件の拒否、保存結果を確認。TEST_DATA_PATHを渡す場合は同時二重取込も確認する。
- agent-browserでPDF3件、PNG1件をOCR、別名の同一PDFを実際のdropイベントで拒否、Shiftで3件選択、状態の一括変更と一括保存を確認。
- 全書類/発行/受領/郵便物/案件一覧/案件詳細/ダッシュボード/入金支払い/集計/取引先を390x844、768x1024、1440x900で確認。ページ幅の超過なし、表示中の操作ボタンの高さ44px以上（スマホ・タブレット）。新規書類画面はライト/ダークも確認。
- Google Vision/OpenAI経由の実書類OCR、Synologyでの稼働、実機iOS PDF表示、全ての既存帳簿の支払記録と状態の突合はこのローカル検証に含まない。OCR結果は原本確認が必要。

## リリース前の別確認

- 既存依存関係に `npm audit --omit=dev` の警告22件（critical 1/high 13を含む）がある。このUI作業で破壊的な依存更新は行っていない。
- `normalizeReleaseUsers` に既存の固定初期パスワードへ戻す処理が残る。秘密情報そのものはここに記載しない。正式な認証運用の見直し対象。
- 更新キューは単一Synologyアプリプロセスを想定。複数インスタンス構成にする場合はDBトランザクション/排他が必要。
- 旧データの二重登録を自動削除したり、本番の既存データを一括修正したりする変更ではない。
