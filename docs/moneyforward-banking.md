# Money Forward 口座とカード明細の連携

TRIANGLE Invoice OS の `/banking?company=JAPAN` に、連携口座・クレジットカードの明細を取引月ごとに取り込む。管理者と経理担当だけが閲覧・編集できる。請求書担当・郵便物担当には表示しない。

## 接続設定

1. Money Forward クラウド会計の対象事業者で、銀行・カードの連携エラーや再認証待ちを解消する。このアプリから金融機関側の更新は行わない。
2. 管理者の承認を得て API キーを用意する。キーは発行ユーザーの権限を継承するため、可能なら閲覧専用の連携ユーザーを使う。キーをチャット・Git・スクリーンショットに記録しない。
3. Synology のアプリコンテナに次の環境変数を設定する。値は `.env.example` ではなく、非公開の実行環境に保存する。

```dotenv
APP_URL=https://invoice.kuremasato.com
MONEYFORWARD_JAPAN_API_KEY=
MONEYFORWARD_JAPAN_OFFICE_CODE=
```

`APP_URL` はブラウザーで利用する公開URLと一致させる。古いNASアドレスや `localhost` のままだと、同期開始時の送信元チェックで拒否される。Cloudflare経由の本番では上記URLを使い、チェック自体は無効化しない。既存コンテナの環境変数を変更した場合は、設定ファイルの保存や単なる再起動だけでなく、コンテナの再作成で反映する。

事業者番号は `0000-0000` 形式。中国側も必要な場合だけ `MONEYFORWARD_CHINA_API_KEY` と `MONEYFORWARD_CHINA_OFFICE_CODE` を設定する。同じ事業者を両社に重複接続することや、既存明細のある会社を別事業者へ差し替えることは拒否する。

4. 環境変数を反映して再起動後、「口座・カード明細」の「同期」から初回同期を実行する。取得可能な会計期間の最初の日から今日まで、全口座・カードを月単位で取得する。
5. 必要なら管理者が「自動同期」を有効にする。常時稼働する単一の Synology アプリプロセスが6時間ごとに同期する。初期値は無効。停止中は実行せず、復帰後に追いつく。

## 分類と保存

- 月は元明細の取引日から自動判定する。口座・勘定科目・入出金・確認状態・摘要で絞り込める。1ページ50件。
- Money Forward の勘定科目と補助科目を取り込み、アプリ独自の科目・補助科目も追加・編集・削除できる。使用中の科目は削除不可。連携元の科目名は Money Forward 側で編集する。
- 摘要の完全一致・部分一致、口座、入出金、優先順位を指定して自動分類する。手動編集済み・確認済みの明細はルールで上書きしない。
- SHIFTクリックで表示ページ内の範囲選択ができる。選択行へ科目・扱い・確認状態を一括設定し、「すべて保存」で確定する。補助科目は各行で指定する。
- 未保存でフィルター・月・メニューリンクを切り替えると、「保存して移動」「破棄して移動」「キャンセル」を選べる。ブラウザーの戻る操作は対象外。再読み込み・タブを閉じる場合はブラウザー標準の警告を使う。
- 「振替・カード精算」「対象外」、または連携元から消えた明細は集計から除外する。カード利用と銀行引き落としの二重計上を避けるには、引き落とし側を「振替・カード精算」にするルールを設定する。金額だけで自動的に振替と断定しない。
- 表示金額は取り込んだ明細の入出金・返金・利用額であり、預金残高や損益計算書ではない。手動で科目を空にした行も手動編集として保護する。

## 取得の範囲と整合性

- ブラウザーのログインとは別に API キー設定が必要。ブラウザーのパスワードやセッションは保存・流用しない。
- 対象はクラウド会計 API が返す全連携口座とその明細。金融機関が提供していない過去履歴や、Money Forward 自体に未取得の明細は取り込めない。
- 通常同期は前回の全体同期成功日から90日前まで遡る。過去期間の修正には全期間再同期または期間指定を使う。期間指定の成功は通常同期の基準日時を進めない。
- 全ページを取得・検証できた月だけ保存する。途中失敗では取得済みの月を保持し、同じモード・期間の再実行で未完了の月から再開する。再同期は事業者と明細IDで更新し、重複追加しない。
- 元の摘要・金額・日付が変わっても、手動科目とメモは維持する。元明細が変わった行は未確認へ戻す。連携元から消えた行も削除せず「元明細なし」で残す。
- 元明細・同期履歴は Undo 対象外。分類の Undo は、後から同期された金額・取引日を巻き戻さない。同期・保存・Undo は同じ書き込みキューで処理する。
- **Money Forward への仕訳書き戻し、振込、請求書の自動消込は行わない。** 既存の入出金記録・請求書の支払済み状態とは分離し、売上や支払を勝手に増やさない。
- 同期時間の上限は約20分、月内最大200ページ（1ページ500件）。API制限・応答不整合時は成功扱いにせず、画面にエラーを表示する。
- 複数レプリカ・複数Nodeプロセスでの同時稼働には対応していない。増設する場合は先に共有ジョブキューとDBトランザクションロックへ移行する。

## 検証

`npm run test:banking` は模擬APIだけを使い、再同期、全ページ取得、月末・閏年、手動編集保護、権限、途中再開、保存競合を検証する。実口座への接続確認は別途必要。

`node --conditions=react-server --import tsx tests/prepare-banking-preview.ts` はOSの一時フォルダーに架空の口座明細を作成する。出力されたパスを `DATA_DIR` に指定し、`DATABASE_URL` と Money Forward の各環境変数を空にしてローカル起動する。検証用ログインは `admin@example.invalid`、パスワードは `local-banking-test-only`。このデータを本番へコピーしない。
