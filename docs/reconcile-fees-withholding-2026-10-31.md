# 照合の手数料差額処理と源泉徴収（2026-10-31）

対象: 銀行・請求書照合（`/banking/reconcile`）、`src/lib/bank-reconciliation.ts`、`bank-reconciliation-allocation.ts`、`bank-reconciliation-matching.ts`、支払記録の表示。

## P2-10 差額を支払手数料で処理

振込手数料のせいで銀行明細と請求額がわずかに食い違うとき、差額を支払手数料として扱って照合を完了できる。向きで意味が変わる。

| 向き | 状況 | 扱い |
|---|---|---|
| 入金（発行請求書） | 先方が手数料を差し引いて振り込んだ（銀行 99,340 / 請求 100,000） | 支払記録は請求額 100,000（`feeAmount: 660`、`feeCategoryId`）、照合リンクの金額は銀行入金 99,340、`fee.borneBy = "payer"`。請求書は入金済み。先方負担分の手数料は支払記録の内訳として残る |
| 出金（受領請求書） | 自社の銀行が手数料を上乗せした（銀行 100,660 / 請求 100,000） | 支払記録・照合リンクの金額は請求額 100,000、`fee.borneBy = "bank"`。手数料 660 は銀行側の消し込みに数え、明細に科目があれば記帳の科目分割（元の科目 100,000 ＋ 手数料科目 660）を自動で付ける。科目がない・既に分割がある・整数円でない場合は分割せず、結果の注記で知らせる |

- 入力: `ReconcileInput.fee = { amount, categoryId? }`。新しい支払記録（`mode: "new"`）のみ。手数料科目は同じ会社・事業者の有効な親科目。一括配賦では1件の配賦にだけ付けられる。
- 残額の数え方: `linkBankCents`（銀行側 = 金額 + 銀行負担手数料）と `linkPaymentCents`（支払記録側 = 金額 + 先方負担手数料）を、照合可否の判定・照合状況・要再確認の判定・支払記録一覧の照合済み額・口座明細の「請求書」ラベルで共通に使う。これにより、手数料ありの照合が「一部照合」「支払記録あり・銀行未照合」に見えなくなる。
- 画面: 配賦明細が1件・新規記録で、差額が 0 より大きく 1,100 円または請求額の 2% 以内のとき、「差額 ¥X を振込手数料として…」のチェックと手数料科目の選択を表示する。チェックすると配賦額を銀行残額（入金）または請求額（出金）に合わせる。配賦合計の横に「うち手数料」。支払記録一覧には「（銀行入金 ＋ 手数料）」、照合記録には「（手数料 … 先方差引 / 込み）」を表示。
- エージェント API `reconcile.confirm` / `reconcile.batch` の `payload.fee` でも同じ処理ができる。

## P2-11 源泉徴収ありの請求書

- 受領請求書の `total` は差引支払額（税込総額 − 源泉徴収税額）であるのが本来の状態。照合状況の請求書行に `withholdingAmount`、`netPayable`、`withholdingMismatch`（total が差引支払額と一致しない）を添える。
- 候補の採点: 不一致の請求書では差引支払額の未払い分も一致対象にし、一致したら「源泉徴収後の差引支払額と一致」と理由を付け、「請求書の金額を確認してください」と警告する。一致している請求書は従来どおり。
- 配賦画面に「源泉徴収 ¥X 差引後の支払額 ¥Y」を表示し、不一致なら注意色で示す。請求書の金額自体はこの画面では直さない（受領請求書の編集で訂正）。

## 変更しないこと

- 既存の照合リンク・支払記録は書き換えない（`fee` のないリンクは従来どおり金額のみで数える）。
- 手数料の仕訳そのもの（会計ソフト側の仕訳作成）は扱わない。明細の科目分割と支払記録の内訳までが範囲。
