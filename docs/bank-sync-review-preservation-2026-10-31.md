# 同期時の確認状態の維持と同期の影響レポート (2026-10-31)

## 背景

2026-10-31 11:34 の自動同期（6時間ごと）で、カード口座の2026年8月分242件の `reviewed` が一斉に false になった。金額・日付・摘要・入出金は不変で、Money Forward 側の仕訳状態（`journalizing_status`）が none から registered に変わっただけだった。原因は `mergeBankTransactions` が連携元の仕訳状態とメモまで「明細の変更」と見なし、1項目でも違えば `reviewed: false` で上書きしていたこと。

## 変更後の動き

- 同期で比較する項目を2つに分ける。
  - 本体: 口座、取引日、金額、入出金、摘要。これが変わった明細と、元明細がなくなった明細だけ確認が外れる。元明細が再び現れた明細も本体扱い。
  - 付随: 連携元の仕訳状態、連携元メモ。これだけが変わった明細は、確認状態・科目・補助科目・メモ・分割・保留・扱いを維持し、`updatedAt` だけ進む。
- 連携元が「対象外」にした明細を自動分類の行で対象外扱いに切り替える既存の動きは維持する（手動分類の行は変えない）。
- 同期ごとに `bankSyncRuns` へ記録を残す。追加件数、本体変更、付随のみ、元明細なし、復帰、確認解除の件数と、変更された明細ごとの前後値、確認が外れた明細の同期前の確認状態・科目。
- 口座・カード明細の同期状態の行に「同期の影響」ボタンを追加した。同期ごとの件数と一覧を開き、確認が外れた明細を選んで同期前の確認状態・科目へ一括で戻せる。残っている戻せる件数はボタンに表示する。

## 戻せる条件

- その同期で確認が外れた明細であること（確認が外れていない行、付随のみの行は対象外）。
- 同期後に編集されていないこと（`updatedAt` が同期直後の値と一致）。編集済みの行は「同期後に編集されています」と表示し対象外。
- 元明細がある、保留中でない、同期前の勘定科目・補助科目が有効、資金移動と照合されていない。
- 復元は選択した明細をまとめて検証してから保存する。対象外の明細は理由付きで返し、残りは保存する。復元は通常の「元に戻す」で取り消せる。

## 上限

- 同期記録は会社ごとに直近20回。変更明細の記録は1回あたり500件まで。超えた場合は確認が外れた明細を優先して残し、「記録は一部のみ」と表示する。
- 監査ログ（`BANK_SYNC_MONTH`）には件数だけを残す。明細ごとの差分は同期記録側にある。

## 既存データの補正（承認後に別作業）

2026-10-31 の242件は、この変更より前の同期で外れたため同期記録がない。`scripts/migrations/restore-reviewed-after-sync.mjs` で候補を出す。

```bash
node scripts/migrations/restore-reviewed-after-sync.mjs --data /volume1/docker/triangle-invoice-os/data/app-data.json --since 2026-10-31T02:30:00Z --until 2026-10-31T02:40:00Z --month 2026-08 --out tmp/restore-reviewed-report.json
```

- 候補: 会社 JAPAN、`classificationSource` が MANUAL、`reviewed` が false、元明細あり、保留なし、科目または分割または通常以外の扱いがあり、`updatedAt` が指定した時間帯に入る明細。`--month` と `--account` でさらに絞る。
- 既定はドライラン。一覧と口座別・月別の件数を出し、`--out` で JSON を保存する。何も書き込まない。
- `--apply` は `data/backups/<timestamp>-restore-reviewed-after-sync.json` にバックアップを作ってから `reviewed` を true にし、監査ログに移行の記録を1件追加する。
- `--restore <backup>` でバックアップから戻す。戻す前の現行ファイルも `before-restore` として保存する。
- 本番ファイルは NAS 上にある。実行はユーザー承認後に、アプリを止めるか同期が走らない時間帯に行う。
