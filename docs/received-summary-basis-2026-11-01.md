# 受領請求書の集計基準（P0-5 / 2026-11-01）

## 原因と合成データでの再現

一覧は債務グループの支払対象外だけを除外し、アーカイブ・却下を未払いに含めていた。ダッシュボードはこの2状態も除外していた。カードの集計元は検索・絞り込み後の書類だったが、集計条件や各金額の意味を表示していなかった。

修正前の合成データで一覧は未払い8件・212,500円、ダッシュボードは6件・42,500円。差額170,000円はアーカイブ90,000円と却下80,000円の2件だった。

## 修正

- 共通の receivedPayableSummary（src/lib/received-invoice-payables.ts）をダッシュボードと一覧で使用する。削除・アーカイブ・却下・債務グループの支払対象外を未払いから除外し、残額は既存の receivedPaymentSummary に統一する。
- 会社・閲覧権限・削除済み案件の制限は従来どおり各呼び出し元の visibleProjects による。行の保存状態や金額、支払記録、mailProcessed は変更しない。
- 支払記録は生存しているEXPENSE・当該受領請求書への単独の紐付けを対象にする。取消済み・INCOME・発行請求書にも同時に紐付く異常な記録は含めない。銀行明細の金額を別途加算しない。ダッシュボードも既存の支払管理と同じ規則になる。
- ダッシュボードが従来持っていた非有限数の除外を共通の支払計算でも維持。小数点以下2桁単位で集計し、過払いを別の請求書の未払いから引かない。
- カード直上に現在の絞り込み・検索語（なしの場合も表示）・期間を表示する。請求日の期間指定は既存画面にないため全期間。月の開閉は見た目だけで集計を変えない。ボタンの件数が検索前であることも明記する。
- 未払いの一覧列は除外理由付きの「対象外」、詳細は「未払い集計対象外（理由）」と表示する。除外による0円を支払済み扱いしないため、「支払済み」絞り込みと支払色は実際の支払完了を使う。金額未設定の0円書類や、記録のないPAIDは支払済み絞り込みに入れない。保存された状態自体は変更しない。
- PAIDへ変更するガードは集計除外前の書類単独の残額を使う。詳細の支払記録パネルも従来の残額と操作可否を維持する（債務グループの対象外は従来どおり0）。集計除外を理由に保存処理を緩めたり支払記録を作ったりしない。

## カードとダッシュボードの対応・残る違い

| 表示 | 集計内容 |
| --- | --- |
| 合計 | 現在の絞り込み・検索に合致する書類の差引支払額（total）合計。全件表示ではアーカイブや債務グループの旧書類も含む書類の総額であり、債務の総額ではない |
| 支払済 | 同じ書類への有効な支払記録合計。一部支払・過払いも含む。支払済み状態の書類総額ではない |
| 未払い | 同じ書類のうち除外条件に該当しないものの残額。未払い件数は残額が正の書類数 |
| ダッシュボードの未払い | 全期間の未解消債務。検索なしの一覧「未払い」と件数・対象ID・金額が一致 |

- 検索や他の絞り込みをかけた一覧のカードはその集合だけを集計するため、ダッシュボードの全体額とは異なり得る。表示条件をカードに明示する。
- ダッシュボードの決算年度選択はグラフを切り替えるもので、現在の未払いを限定しない。一覧も過年度・請求日なしを含める。日付なしは期限の絞り込みには含めない。
- 全件表示の合計・支払済と未払いには集計上の除外差があり、過払いもあるため「合計－支払済＝未払い」が必ずしも成り立たない。カード内の説明と除外件数で明示する。
- 支払記録のないPAIDは両方の未払いに残し、ダッシュボードでは支払記録要確認として扱う。ダッシュボードの期限超過/期限間近のリマインダー件数は二重の支払要求を避けるためこのケースを除外する従来仕様を維持。一覧の期限絞り込みは書類の期限を調べるため残額のある書類を表示する。今回一致を保証するのは「未払い」件数・金額。
- 詳細の支払記録パネルは1書類の記録確認・訂正用で、アーカイブ等でも従来どおりその書類単独の残額を表示する。上部の集計対象からは除外される。
