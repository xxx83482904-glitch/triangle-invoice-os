# 支払記録の整理（受領請求書） 2026-10-31

## 背景

受領請求書の状態を「支払済み」にすると、銀行と無関係に請求額と同額の支払記録が自動で作られていた。OCR 取込や郵便物の処理済み操作でも同じ経路が動き、督促中で未払いの税金にも支払記録が付いた。状態を戻しても記録は残り、取り消す画面がなく、差引支払額を登録済み支払額より小さくできないため読み違えた金額を直せなかった。金額を上げると差額の支払記録がもう1件できた。

## 変更後の動き

- 支払記録を作るのは、銀行・書類照合（`source: BANK_RECONCILIATION`）と明示的な手入力（`source: MANUAL`）だけ。状態の変更、郵便物の処理済み、OCR 取込、郵便物からの受領請求書作成は支払記録を作らない。
- 「支払済み」は支払記録から決まる。状態を支払済みにできるのは、支払記録か銀行照合が差引支払額を満たしているときだけで、満たさない場合は保存を拒否し、支払記録の登録へ誘導する。一覧・詳細の状態選択では未払いがあると「支払い済み」を選べない。
- 郵便物の「処理済み」は書類処理の状態だけを変え、支払状態には触れない。
- 金額の訂正は支払記録と独立。差引支払額を登録済み支払額より小さくしても保存でき、超過分は「支払記録の合計が請求額を超えています」として表示する（整合性チェックの対象）。金額を上げても支払記録は追加されず、未払いとして残る。
- 受領請求書の詳細に「支払記録」の区画を追加。記録ごとに金額・支払日・方法・出所（銀行照合 / 手入力 / 旧ステータス変更（自動作成） / 手入力（旧））、銀行照合済みかどうかと照合額、メモ、変更履歴を表示する。
- 支払記録の操作（権限 `manage:expensePayments`）: 手入力での登録（支払日・金額必須、未払い額まで）、金額・支払日の修正（理由必須）、取消（理由必須）。銀行照合済みの記録は照合を解除するまで修正・取消できない。すべて監査ログと「元に戻す」の対象。
- 入金・支払い管理画面の登録も同じ経路（`recordPayment`）を使い、`source: MANUAL` が付く。
- 旧データの表示: `source` のない記録は、方法が「ステータス変更」またはメモが「ステータス変更で支払済み…」なら「旧ステータス変更（自動作成）」、それ以外は「手入力（旧）」として表示する。登録状態が支払済みなのに支払記録が足りない書類は警告を出す（自動では書き換えない）。

## 変えていないこと

- 銀行・書類照合で作られる支払記録と、全額到達時に書類を支払済み・郵便物を処理済みにする動き。
- 発行請求書の状態変更からの入金記録（`INVOICE_STATUS`）。別途整理する。
- 本番の既存データ。補正は下記スクリプトのドライランまで。

## 既存データの補正（承認後に別作業）

`scripts/migrations/payment-records-cleanup.mjs` は、方法「ステータス変更」またはメモ「ステータス変更で支払済み…」で、銀行照合に使われていない支払記録を列挙する。

```bash
node scripts/migrations/payment-records-cleanup.mjs --data /volume1/docker/triangle-invoice-os/data/app-data.json --out tmp/payment-records-report.json
```

- 既定はドライラン。書類ごとに支払先・原本名・請求額・状態・他の支払記録・うち銀行照合・超過額と提案を出す。提案は「取消（銀行照合で全額確認済み。自動作成分は重複）」「取消（書類は差し戻し・アーカイブ）」「取消候補（支払の証拠なし。実際に支払済みなら手入力の支払記録として登録し直す）」。
- `--apply` は `data/backups/<timestamp>-payment-records-cleanup.json` を作ってから対象を取消（履歴に理由を残す）し、支払記録が請求額に足りなくなった書類を支払予定に戻す。郵便物の処理済みと銀行照合は変更しない。`--only` / `--exclude` で対象を絞れる。
- `--restore <backup>` で戻す。
- 本番ファイルは NAS 上にある。アプリ停止中か同期が走らない時間帯に、ユーザー承認後に実行する。
