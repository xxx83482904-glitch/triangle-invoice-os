# エージェント用 API v1（2026-10-31）

対象: `src/app/api/agent/v1/*`、`src/lib/agent-tokens.ts`、`src/lib/agent-api.ts`、利用者管理画面のトークン発行。

## 目的

外部のエージェントやスクリプトが、画面と同じ業務ルール（同じライブラリ関数）を通して日本版のデータを読み書きできるようにする。画面操作の代替であり、ルールを迂回する裏口ではない。

## 認証とトークン

- `Authorization: Bearer tri_...`。トークンは管理者（`manage:users`）が「利用者管理」画面で発行する。平文は発行直後に一度だけ表示し、保存しない。保存するのは SHA-256 ハッシュと表示用の先頭12文字（`prefix`）。
- トークンは利用者に紐づく。実効権限は **利用者ロールの権限 ∩ トークンの scopes**。利用者がその権限を持たないスコープは発行できない。利用者が無効（承認待ち・却下・削除）になるとトークンも使えない。
- 会社スコープは `JAPAN` 固定。有効期間は 1〜365 日。取消は即時。読み取りでは `lastUsedAt` を更新しない（書き込み時のみ）。
- スコープ: `bank:read`（明細・書類・照合・支払記録・支払先・案件・科目・同期履歴の読み取り）、`integrity:read`、`bank:write`（分類・確認・記帳メモ）、`reconcile:write`、`payments:write`、`received:write`、`mail:write`、`partners:write`。
- 監査ログには `origin: { kind: "agent", tokenId, reason }` を記録する。トークン本体は記録しない。Money Forward 同期は `kind: "sync"`、それ以外の省略は利用者操作。

## 読み取り `GET /api/agent/v1/<resource>`

リソース: `bank-transactions` `received-invoices` `issued-invoices` `payments` `reconciliations` `mail-documents` `vendors` `projects` `categories` `sync-runs` `integrity`。

共通パラメータ: `company`（既定 JAPAN）、`start` / `end`（日付。明細は取引日、書類は発行日、支払は支払日、郵便物は月）、`updatedSince`、`account`、`status`（明細は扱い、書類は状態、照合は `conflict` / `valid`、郵便物は分類）、`side`、`reviewed`、`q`（部分一致）、`kind`（integrity の種類）、`limit`（1〜500、既定100）、`cursor`（前回の `nextCursor`）。

応答: `{ resource, company, total, limit, cursor, nextCursor?, items[] }`。明細には表示ラベル `classification` を添える。照合には `issue`（要再確認の理由）を添える。`integrity` は `counts` / `severity` / `truncated` も返す。`GET /api/agent/v1` は仕様の要約を返す（認証不要・データなし）。

## 書き込み `POST /api/agent/v1/batch`

```json
{
  "idempotencyKey": "2026-10-31-journal-001",
  "dryRun": true,
  "atomicity": "batch",
  "reason": "10月分の仕訳確認",
  "operations": [
    { "op": "bank.classify", "target": { "id": "mf:JAPAN:0000-0001:transaction:123:" }, "expect": { "updatedAt": "2026-10-30T01:02:03.000Z" }, "payload": { "categoryId": "mf:JAPAN:0000-0001:category:5:", "reviewed": true, "memo": "請求書 #123" } },
    { "op": "reconcile.confirm", "expect": { "transactionDate": "2026-10-08", "amount": 12000, "content": "カ）テストデザイン" }, "payload": { "invoiceKind": "issued", "invoiceId": "...", "amount": 12000 } }
  ]
}
```

- `target.id` か、明細なら `expect`（`transactionDate` + `amount` + `content`）で対象を指定する。複数一致は 409。`expect.updatedAt` があれば現在値と一致しないと 409 で拒否する。
- `op` と呼ぶ関数: `bank.classify`→`saveBankEdits`、`bank.bookkeeping`→`saveBankBookkeeping`、`reconcile.confirm`/`reconcile.batch`/`reconcile.remove`/`reconcile.reaffirm`→照合ライブラリ、`mail.link`/`mail.unlink`、`payment.record`/`payment.cancel`/`payment.adjust`、`received.update`→`applyReceivedInvoiceFields`、`vendor.create`、`project.create`。推測のまま確認済みにする場合の `acknowledgeGuess`、取消の `reason` 必須などのルールは画面と同じ。`mail.recreateInvoice` は未対応（画面の「作り直す」を使う）。
- `dryRun: true`: データの複製で全操作を実行し、行ごとの `status` / `error` / `changes`（対象コレクション・id・前後）を返す。保存しない。
- `atomicity: "batch"`（既定）: まず複製で予行し、1件でも失敗なら 422 で結果を返して保存しない。全件成功なら保存ロック内で再実行して1回で保存する。
- `atomicity: "row"`: 操作ごとに独立して保存し、成功・失敗を混ぜて返す。
- `idempotencyKey`: 同じトークン・同じキー・同じ本文なら保存済みの結果を `replayed: true` で返す。本文が違えば 409。7日で失効。
- 本文は 1MB、操作は 200 件まで。応答は `{ company, dryRun, atomicity, results[], succeeded, failed, skipped, applied }`。

## CLI

`scripts/agent-cli.mjs`（`TRIANGLE_API_URL` / `TRIANGLE_API_TOKEN` は `.env.local` にのみ置く）: `describe`、`read <resource> k=v...`、`dry-run <batch.json>`、`apply <batch.json>`。

## 変更しないこと

- Server Actions は使わない（ID が変わるため）。既存画面の処理は変更していない。
- 中国版・本番データへの操作は本 API の対象外（会社スコープは JAPAN 固定）。
