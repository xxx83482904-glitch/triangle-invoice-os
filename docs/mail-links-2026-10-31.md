# 郵便物と受領請求書の参照整合 2026-10-31

## 背景

郵便物12件が「受領請求書」扱いのまま、参照先の受領請求書が存在しなかった（削除されたとみられる）。郵便物の画面から作り直す操作がなく、受領請求書を削除しても郵便物側の参照が残っていた。原本ファイルが欠落している郵便物（3件）の警告もなかった。

## 変更後の動き

- 参照の解決は「削除されていない受領請求書で、案件が有効かつ同じ会社」のものだけを連携先とみなす。参照先が削除・移動されている郵便物は、一覧の保存先に「受領請求書（参照切れ）」と赤い「参照切れ」バッジを表示し、画面上部に件数を出す。
- 受領請求書を削除したとき（郵便物フォルダーからの削除、一括削除、全書類からの削除）、その受領請求書を参照していた他の郵便物を未連携（`relatedReceivedInvoiceId` なし、処理済み解除）に戻す。
- 参照切れ・未連携の郵便物の編集欄に2つの操作を用意する。
  - 「受領請求書を作り直す」: 既存の反映フォームを使い、この郵便物から受領請求書を新規作成する。
  - 「既存の受領請求書へ再連携」: 候補（同じ原本ファイル、同じファイル名、支払先名の一致、同じ月）を先頭に、すべての受領請求書から選んで連携する。連携時に分類が請求書・領収書以外なら請求書にし、処理済みは受領請求書の支払完了に合わせる。別の有効な受領請求書と連携済みの郵便物は先に解除が必要。
- 連携済みの郵便物には「連携を解除（未連携に戻す）」を追加した。受領請求書自体は削除しない。
- 原本ファイルがローカルの保存先（`UPLOAD_DIR`、旧 `public/uploads/received-invoices`）に見つからない郵便物・受領請求書は「原本なし」バッジと上部の件数で警告する。ファイルをデータベースに保存している構成では判定しない。
- いずれの操作も権限は郵便物の編集権限（`manage:mailSorter` / `manage:receivedInvoices` / `upload:receivedInvoices`）と会社スコープをサーバー側で確認し、監査ログと「元に戻す」の対象になる。

## 既存データの点検（報告のみ）

`scripts/migrations/mail-link-report.mjs` は参照切れの郵便物と候補、原本ファイルのない書類を一覧にする。データファイルには書き込まない。

```bash
node scripts/migrations/mail-link-report.mjs --data /volume1/docker/triangle-invoice-os/data/app-data.json --uploads /volume1/docker/triangle-invoice-os/uploads --out tmp/mail-link-report.json
```

- 参照切れごとに、参照先の状態（削除済み／存在しない）、削除された書類の支払先・金額、候補（同じ原本ファイル、同じファイル名、支払先名の一致、削除された書類と同じ支払先・金額）と提案（候補ありなら再連携、なければ作り直し）を出す。
- `--uploads` を指定すると、郵便物と受領請求書のファイル名で保存先を確認し、見つからないものを列挙する。複数の保存先はカンマ区切り。
- 補正は画面の「作り直す」「再連携」で1件ずつ行う。スクリプトから自動では変更しない。
